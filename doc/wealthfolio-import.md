# Importing Trading 212 History into Wealthfolio

This guide documents how to import `trading212-history.csv` cleanly into **[Wealthfolio](https://github.com/wealthfolio/wealthfolio)** ([official docs](https://wealthfolio.app)) without breaking cash balances, performance charts, or asset price history.

> [!NOTE]
> Use `trading212-history.csv` (generated by `python main.py --history`) as your source for Wealthfolio. Because it comes from Trading 212's official `/equity/history/exports` report, it includes AutoInvest Pie trades, dividends, withholding taxes, cash interest, and debit card cash movements.

---

## 1. Before You Import: Account Setup & Clean Reset Tips

### Account Type
In Wealthfolio (**Settings → Accounts**), create your Trading 212 brokerage account as type **`Securities`** with your account base currency (e.g., `EUR`).

- **Why the Spending tab stays empty on a `Securities` account:** Wealthfolio only feeds the **Spending & Budgets** tab from **`Cash`** or **`Credit Card`** accounts. Outflows (`WITHDRAWAL`) inside a `Securities` account are treated as portfolio **Distributions** so regular brokerage withdrawals aren't mistakenly double-counted as consumer spending.
- **If you want both Portfolio + Card Spending later:** Because Trading 212 merges both your Main Pot and Spending Pot into one CSV (putting merchant info in `Merchant name` and `Merchant category`), you can create two accounts grouped under the same Account Group in Wealthfolio (`Trading 212` as `Securities` + `Trading 212 Card` as `Cash`) when automating imports via a script or addon.

### Re-importing After Fixing Mappings
If you previously imported with wrong mappings (for example, Wealthfolio's built-in Trading 212 template):
1. Export/backup your Wealthfolio database or delete the existing `Trading 212` activities/account so old misclassified rows don't linger or trigger duplicate-skipping against corrected rows.
2. Delete any wrongly resolved stale assets (e.g., `Litecoin USD` for `LTC`, or European `XETR` duplicates for US stocks) before or right after re-importing so future lookups don't match them.

## 2. CSV Column (Field) Mapping

During Wealthfolio's **Map Columns** step, map `trading212-history.csv` columns as follows:

| Wealthfolio Field | Trading 212 CSV Column | Notes |
| :--- | :--- | :--- |
| **`date`** | `Time (UTC)` | Exact UTC timestamp |
| **`activityType`** | `Action` | Mapped in Step 3 |
| **`symbol`** | `Ticker` | Asset ticker |
| **`isin`** | `ISIN` | Helps disambiguate listings |
| **`quantity`** | `No. of shares` | Supports fractional Pie shares |
| **`unitPrice`** | `Price / share` | Native share quote currency |
| **`amount`** | `Total` | Net cash amount in settlement currency |
| **`currency`** | `Currency (Total)` | Usually `EUR` (or `USD` for USD interest/FX) |
| **`fee`** | **`Ignore`** | **CRITICAL:** See warning below |
| **`tax`** | `Withholding tax` | Tax metadata on dividends |
| **`comment`** | `Notes` | Helpful for FX & interest descriptions |
| **`fxRate`** | `Exchange rate` | FX rate on trade/dividend |
| **`subtype`** | `Ignore` | — |
| **`instrumentType`** | `Ignore` | — |

> [!WARNING]
> **Set `fee` (`Currency conversion fee`) → `Ignore`.**
> Trading 212's `Total` column **already includes** the currency conversion fee on `BUY` / `SELL` rows and **equals** the fee on `Currency conversion` rows. Mapping `fee` to `Currency conversion fee` causes Wealthfolio to subtract those fees a second time.

## 3. Activity Type Mapping (Fixing the Default Template Bugs)

Wealthfolio's built-in Trading 212 template maps `Card debit` and `New card cost` to **`Fee`**, which turns debit card spending into massive negative investment fees and can make Time-Weighted Return (TWR) go below `-100%` (breaking multi-month / All-Time performance charts).

Set every Trading 212 `Action` on the **Activity Preview** screen as follows:

| Trading 212 `Action` | Wealthfolio Activity Type | Why |
| :--- | :--- | :--- |
| `Market buy`, `Limit buy`, `Stop buy`, `Stock distribution`, `Stock split open` | **`Buy`** | Standard acquisitions (includes AutoInvest Pie buys) |
| `Market sell`, `Limit sell`, `Stop sell`, `Stock split close`, `Transfer out` | **`Sell`** | Disposals / splits |
| `Dividend (Dividend)`, `Dividend (Ordinary)`, `Dividend (Dividend manufactured payment)`, `Dividend (Tax exempted)`, `Dividend (Return of capital)` | **`Dividend`** | Dividend income (`Total` is already net cash after tax) |
| `Interest on cash`, `Lending interest` | **`Interest`** | Uninvested cash & share lending interest |
| `Deposit` | **`Deposit`** | Bank/card top-ups (`Contributions`) |
| `Withdrawal` | **`Withdrawal`** | Bank withdrawals (`Distributions`) |
| **`Card debit`** | **`Withdrawal`** | **Change from `Fee`!** Card purchases are cash outflows, not trading fees |
| **`New card cost`** | **`Withdrawal`** *(or `Fee`)* | Physical debit card fee (`Withdrawal` avoids mixing card fees into portfolio Fees) |
| **`Spending cashback`** | **`Credit`** | Debit card cashback credited to cash |
| **`Card credit`** | **`Credit`** | Card refunds credited back to cash |
| **`Dividend adjustment`** | **`Credit`** | Withholding tax adjustments / clawbacks |
| **`Currency conversion`** | **`Fee`** | **Do NOT leave as `Transfer Out`!** Leaving it as `Transfer Out` marks dates as `UNKNOWN_BOUNDARY_TRANSFER` (*"External cash flow provenance is incomplete"*) |

Save this configuration as a custom Wealthfolio Import Template so future imports preserve both your column mappings and activity mappings.

## 4. Review Assets Step (Watch for Ticker Collisions)

Trading 212's CSV puts only a **bare `Ticker`** (`LTC`, `IBM`, `JNJ`) without an exchange suffix. On Wealthfolio's **Review Assets →** screen, check two common pitfalls:

1. **Same ticker across asset classes (Crypto vs Stock):**
   - Example: **`LTC`** (`US5021751020`) is **LTC Properties, Inc.** (`EQUITY:LTC@XNYS` in `USD`), **not** `Litecoin` (`CRYPTO:LTC/USD`).
2. **US stocks matching European Xetra (`XETR`) listings:**
   - Bare US tickers that also trade on Frankfurt/Xetra can auto-match to `@XETR` (`EUR`) instead of `NYSE`/`NASDAQ` (`USD`), which can cause missing historical quotes (`PARTIAL_UNPRICED`) and currency mismatches.
   - Always check multi-listed US tickers such as `ADP`, `AFL`, `EMR`, `GWW`, `IBM`, `JNJ`, `PEP`, `ROP`, `SYY`, `WMT` and ensure they resolve to their US exchanges (`XNYS` / `XNAS`, quoted in `USD`).

## 5. Post-Import Verification & Known Quirks

### 1. Comparing Wealthfolio Cash to Trading 212 UI
Trading 212 splits your available cash in the UI into up to three places:
- **Main Pot** (free investment cash)
- **Spending Pot** (debit card balance)
- **Reserved Cash** (cash locked in open pending `BUY` limit orders)

Wealthfolio combines all three into a single **Cash** balance (`Main Pot + Spending Pot + Pending Reserved Cash`).

Small differences can still occur after a clean CSV import for two reasons:
- **Same-timestamp / identical card or cashback rows skipped as duplicates:** Wealthfolio's CSV importer deduplicates identical `(date, type, amount)` rows, so two identical debit card taps or cashback credits within the same time window may be skipped without affecting investment P&L.
- **Manual `Currency conversion` (`EUR <-> USD`) splits:** Trading 212 exports only the FX conversion fee in `Total` (e.g., `-0.35 EUR`, `-0.87 USD`, `-1.74 USD`) and puts the swapped amounts in `Notes` (e.g., `500.00 EUR -> 580.70 USD`). Your **total Cash converted to EUR** remains accurate, though per-currency sub-balances inside Wealthfolio won't reflect the swap unless manually recorded.

### 2. Troubleshooting Common Wealthfolio Warnings

| Symptom | Cause | Fix in Wealthfolio UI |
| :--- | :--- | :--- |
| **"Calculation note: External cash flow provenance is incomplete" (`Partial data`)** | `Currency conversion` rows were stored as `TRANSFER_OUT` without a matching `TRANSFER_IN` (`UNKNOWN_BOUNDARY_TRANSFER`). | Go to **Activities**, filter **Type = `Transfer Out`**, edit those conversion-fee rows to **`Fee`** (or delete them), and refresh valuations. |
| **"Some valuation rows exclude unpriced held positions" (`Partial data`)** | One or more assets lack historical daily quotes back to your first trade date (e.g., an early position only fetched partial history). | Go to **Market data → History ▾ → `Refresh full history`** (or **`Reset provider history...`** if a ticker stopped mid-history), then recalculate portfolio metrics. |
| **`> 6M` or `All Time` chart shows *"cannot plot because it seems negative"*** | `Card debit` rows (`500+` purchases) were imported as `Fee`, dragging time-weighted returns below `-100%`. | Fix `Card debit` → `Withdrawal` and `fee` column → `Ignore`, then re-import cleanly. |
| **`Asset profile fetch error` when clicking Cash** | Usually happens if non-asset/FX rows created broken asset links or cash positions during a bad import. | Ensure FX conversions use `Fee` (not `Transfer Out` or broken asset symbols) and re-import cleanly. |

## 6. Roadmap Note: Building an Automated Sync Addon

If you later replace manual CSV imports with an automated **[Wealthfolio Addon](https://github.com/wealthfolio/wealthfolio)** (`@wealthfolio/addon-sdk`) or sync script, follow these patterns to avoid manual asset-review fixes forever:

1. **Resolve using Trading 212 `/equity/metadata/instruments` + `ISIN`:** Query Trading 212's metadata endpoint once (requires `Metadata` scope) to get each asset's `isin`, `currencyCode`, and exchange-suffixed internal ticker (e.g., `_US_EQ` vs `.DE`).
2. **Validate search hits strictly:** Reject any market-data candidate whose asset class isn't equity/ETF (blocks `LTC` → `CRYPTO:LTC/USD`) or whose quote currency doesn't match Trading 212's native share currency (blocks `XETR` `EUR` matches for `USD` US equities).
3. **Cache `ISIN` / T212 ticker → Wealthfolio `assetId`:** Store confirmed resolutions in Wealthfolio's `addon_storage` and track incremental sync progress via `brokers_sync_state` before calling `ctx.api.activities.import(...)` (which supports `needsReview: true` for genuinely new/unknown tickers).
4. **Normalize Trading 212 quirks in code:** Map `Card debit` / `New card cost` → `WITHDRAWAL`, cashback/credits/dividend adjustments → `CREDIT`, omit redundant `Currency conversion fee` on trades, and optionally route `Card debit` (`Merchant name` → `comment`) to a separate `Cash` account if you want Spending & Budgets populated.
